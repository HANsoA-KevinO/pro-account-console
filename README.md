# Pro Account Console

个人 Pro 多账号的 Responses 网关与管理平台，支持本机、局域网和单实例服务器部署。每个账号分别保存 Sign in with ChatGPT 授权。Key 与账号解耦：一个 key 可以通过统一路由轮询全部已启用、已授权账号，不收集密码、短信或二次验证代码。

## 部署与发布

当前部署版本为 **0.12.0**。提供 Dockerfile、Linux Docker Compose、HTTPS 反向代理示例、持久化数据目录和 GitHub Actions 回归检查。默认上游 HTTP/SSE 会话路由。

完整安装、首次账号授权、环境变量、升级和备份流程见 [部署说明](deploy/README.md)。源码、镜像和发布包不含本机账号授权、接入 Key、管理员密码或研究日志。

## 启动与首次使用

需要 Node.js 22.13 或更新版本（本机验证使用 Node.js 25.8.1）。

```sh
npm ci
npm start
```

打开 http://127.0.0.1:8787 。

1. 在“账号与授权”中添加账号备注，再点击该账号的“登录此账号”。每个账号由账号所有者在浏览器中完成一次授权。
2. 账号池页面始终显示全部账号，直接查看状态、额度窗口与累计用量。点击该行“连接额度读取”并登录同一个账号，完成独立 Codex 授权后即可自动读取 Codex 限额。启用/停用决定账号是否参与轮询，新账号模型授权后自动加入。
3. 可以继续使用原来的默认 key，也可为成员或 agent 自行添加独立 key；创建 key 时不再选择账号。
4. 把复制的 Base URL、本地 API key 和统一 `/v1/models` 列出的模型名填到支持 Responses 的程序中。

正常访问会在访问令牌过期前按需续期，不需要把 OpenAI 令牌交给成员。若授权被撤销、刷新令牌失效或服务端要求重新验证，平台会提示该账号需要重新授权；本地接入 key 可以继续保留。

## 局域网访问

```sh
npm run start:lan
```

启动时自动寻找私有 IPv4 地址，同时保留 `http://127.0.0.1:8787`。只监听本机回环和选中的内网 IP，不监听所有网卡。终端显示内网 URL；同一局域网的设备可使用该 URL 的 `/v1` 作为 Base URL，继续使用现有接入 key。

内网管理页面使用浏览器自带的 HTTP Basic 登录框，用户名和随机密码保存在权限为 `0600` 的 `.data/lan-admin.json`，重启沿用；管理密码与 agent key 独立。编辑文件中的 `username` 或 `password` 后保存即可即时生效，无需重启，浏览器若记住旧密码需重新输入。密码不能为空；文件缺失或格式无效时内网管理会拒绝访问，本机入口仍可用于修复。HTTP 入口适用于受信任的局域网。账号 OAuth 与 Codex 额度的首次授权仍须在运行网关的电脑上使用本机入口完成，内网可以管理已有账号、查看额度与日志、启动检测及管理 key。

管理会话按访问地址隔离，继续校验 Host、同源请求及 CSRF。内网 IP 随 DHCP 变化时，重新运行 `npm run start:lan` 会发现新地址。普通 `npm start` 仍只开放本机入口。

管理登录有效期为 24 小时，登录会话持久保存在受保护的 SQLite 中，cookie 凭据只存 SHA-256 摘要；服务重启后 cookie 和 CSRF 仍有效。登录一次后，后台刷新和静态资源使用 HttpOnly 会话 cookie，无需每次重新发送 Basic 密码。更改管理密码会立即使旧管理会话失效。仅首次打开页面会发起浏览器登录框；管理 API 的登录状态失效返回明确错误，前端停止后台轮询并尝试刷新页面恢复登录，防止连续弹框或自动刷新循环。

## 多账号与 Key 管理

- 账号：添加、备注改名、独立登录/续期/断开、启用与停用、删除。每行“删除”及详情里的“删除账号”会先显示确认弹窗；确认后退出账号池并清理该账号的本地模型/额度授权和快照。历史用量、质量检查和审计记录保留，日志与筛选注明“已删除”。Key 不需要修改。允许删除原始账号和最后一个账号；空池仍可管理 key、查看历史或重新添加账号。进行中的请求、质量检查或额度同步会阻止删除，需等待完成；等待中的登录会取消，本地额度进程会停止。这里只移除本地接入，不注销 OpenAI 账号，也不撤销官方账号本身。
- 默认 key：保留旧 demo 的 key，使用统一路由，无需修改调用端。
- 独立 key：按需添加，只设置允许模型、每日请求上限、token 暂停阈值和最大并发数，不保存账号绑定。
- 并发设置没有固定的 32 上限，可自行填写有效正整数；平台按你设置的值控制该 key 的并发。
- 每个账号有独立的 `maxConcurrent`，默认 2，可在账号池对应行点击“设置并发”修改，支持 32 以上的有效正整数。页面显示当前进行中请求 / 上限；账号上限按所有接入 key、管理员测试和指纹检测的模型请求合计，与每个 key 自身的上限同时生效。
- Key 轮换：旧 key 立即失效；不会修改其他 key，也不影响上游授权。
- 独立 key 的完整值只在创建或轮换时显示，服务端保存 SHA-256 摘要。忘记后可轮换生成新 key。
- 所有 key 均由统一路由选择本次请求的账号；Key 的限额会跨账号累计，切换路由或账号不会重置限额。
- 每日限额按 Asia/Tokyo 计算。请求上限会计入进行中的请求，认证失败不占已提交请求数。
- token 阈值是“达到后暂停后续请求”的控制，单次请求可能越过阈值。存在未确认消耗时暂停后续受该阈值约束的请求，不把未知消耗当成零。

## 一个全局账号池

- 所有 key 共用一个池，统一轮询已启用、有套餐权限且模型可用的账号。
- 不再配置路由规则、优先级、指定账号池或 key 路由。旧配置会备份，再统一为全账号池。
- 管理账号只需添加/授权、启用/停用、备注与额度记录。Key 仅设置模型权限、请求/token 限额和并发。
- 模型列表读取不会推进轮询，只有通过限额检查并接收的请求推进。
- 新会话和无会话 ID 的请求会跳过已满的账号；全部可用账号均满时自动排队。已绑定会话在原账号等待，不自动换账号；key 自身达到并发上限也会排队。
- 每条请求只尝试一个账号，失败会返回给调用者，不自动换号重试，不改写模型。
- 轮询计数由当前服务进程维护，重启后从第一个可用账号开始。
- 请求体携带 `session_id` 时，仅新会话推进轮询，后续请求继续使用绑定账号；会话绑定持久保存，重启后继续沿用。
- 全部日志默认显示所有账号和所有 key，记录实际使用账号。筛选仅影响日志视图，“显示全部”可恢复全量记录。
- 指纹检测的账号选择只用于固定账号采样，不影响账号池分发或其他页面。

## 会话固定账号

Agent 在创建对话时生成稳定的 `session_id`，同一对话的后续提问和工具调用续接都复用它，新对话生成新值。例如发送到 `/v1/responses`：

```json
{
  "model": "gpt-6-astra",
  "session_id": "chat-123",
  "input": [{"role": "user", "content": "你好"}],
  "stream": true
}
```

`session_id` 是网关字段，不是 OpenAI 的会话存储参数。网关在转发上游前移除它，并根据 Key 条目、实际账号身份和会话生成稳定的上游 HTTP `session-id`／`thread-id` 请求头。每轮保留调用者提交的完整 `input`、原始 Responses 输出项、工具调用及结果；网关不替调用端保存这些内容。

- 相同接入 key 下的同一 `session_id` 固定到首次选中的账号。不同 key 的相同 ID 分开绑定；轮换同一 key 条目的凭据仍保留绑定。
- 新会话轮询当前可用账号，不带 `session_id` 的请求继续按请求轮询。相同会话的续接不会推进轮询。
- ID 必须是 1–256 字符的非空字符串，不包含控制字符或首尾空格；非法值返回 `400 invalid_session_id`，不会占用额度或创建绑定。
- 绑定保存在 SQLite `session_routes` 表中，不会因重启或空闲自动改绑。账号停用、删除、移除中、授权不可用、模型不可用或登录身份改变时，返回 `409 session_account_unavailable`，不自动切换账号。恢复原账号可继续会话；调用端也可明确开始新会话。
- 上游失败不会触发换号或隐藏重试，原会话绑定保留。模型与 key 的权限、额度及并发检查仍适用。
- 响应头 `x-gateway-account-id` 表示实际账号，`x-gateway-session-routing` 为 `assigned`（首次分配）、`reused`（沿用）或 `none`（无会话标识）。
- 日志详情和 CSV 保存 `session_id` 及分配状态；使用 `/api/usage?session_id=chat-123` 或 `/v1/usage?session_id=chat-123` 可筛选，会话 ID 不会取代每次调用独立的日志 ID。

会话固定有助于保持账号一致，但不保证每轮命中上游缓存，也不替 agent 保存对话内容。

### 默认 HTTP/SSE 会话缓存与工具续接

正式服务默认每轮独立提交完整历史到上游 HTTP/SSE。外部地址与 Key 不变，客户端只需继续携带稳定的 `session_id`。同一 Key 条目、实际账号身份和会话得到同一上游 UUID，重启、令牌刷新或轮换同一 Key 的凭据不会改变它；不同 Key、账号或登录身份分开隔离。缓存命中仍取决于完整渲染前缀、模型设置及上游缓存可用性。

相同会话在已有队列中串行，等待期间不额外占用账号或 Key 的并发位；其他会话按原有并发配置运行。请求体 `prompt_cache_key` 等已有缓存控制字段继续透传，客户端不需要填写缓存键。当前 Pro 路线实测返回的 `prompt_cache_key` 跟随上游 `session-id`，不要将其等同于任意调用者填写的键，也不要将此行为推广到其他 API 路线。

网关接收上游 `x-codex-turn-state` 路由状态。只有下一次完整输入包含上一轮完整输入及原始完整输出、仅追加工具结果，并且参数与授权令牌仍一致时，才将状态原样回传。出现新用户消息、重复或改写历史、设置变化、令牌刷新、流中断或无法确认的续接时重新开始一轮，不将上一轮状态用于整段对话。历史项只保留哈希，路由状态仅在内存中保存，空闲 10 分钟清理，最多保留 128 个已完成会话的状态；这个数量不限制活跃推理并发。

响应头 `x-gateway-upstream-transport=http`、`x-gateway-upstream-session-mode=full_history`、`x-gateway-upstream-session-id` 和 `x-gateway-upstream-turn-routing` 可确认实际路径。日志详情和 CSV 记录上游会话 ID、发送项数、路由状态是否发送／接收、返回缓存键哈希及其是否匹配会话 ID，不保存上游路由状态原文。上游失败、部分流和连接中断不隐藏重试，也不换号。

2026-10-12 的 12 次合成纯 HTTP 对照中，固定上游会话头的两次重复输入分别命中 95.2%，只填写请求体缓存键或每次更换会话头的组均为零。另三轮每次独立提交完整历史、未填写请求体缓存键的对话，后两轮合计命中 94.4%。此前真实研究的低命中 HTTP 样本缺少此请求头，不能据此认为 HTTP 本身不能稳定复用缓存。详见 `reports/codex-http-caching-findings-20261012.json`。依据：[官方 HTTP/SSE 配置](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)、[Codex 会话与缓存亲和性源码](https://github.com/openai/codex/blob/ff6aec96948b70d94983af2641a6b67c94faeff5/codex-rs/core/src/client.rs#L575-L596)。

同日正式部署后，Sci-Pegasus 使用原有地址和 Key 的 Write → Read → Write 工具流程共 4 次模型请求全部完成。首次缓存为零，后续三次分别命中 97.2%、98.2%、97.3%，后续输入加权合计 97.5%，包括首次输入的整体比例为 73.4%。账本与客户端用量逐条一致，同账号、同上游会话 UUID，三次工具续接均回传本轮路由状态，每次仍提交完整历史。131 项模拟回归全部通过。报告：`reports/http-session-deployment-20261012.json`。这是有界工具流程验证，不是长时间业务命中率保证。

### 可选 WebSocket 会话续接

明确设置 `GATEWAY_UPSTREAM_SESSION_TRANSPORT=websocket` 后，带 `session_id` 的接入请求使用持久 WebSocket，外部接口仍为 `/v1/responses` 的 HTTP JSON 或 SSE。连接按 Key 条目、实际账号、模型和会话隔离，同会话请求在已有队列中串行；等待期间不会额外占用账号或 Key 的并发位。不同会话继续按配置并发。

Agent 每轮仍提交完整历史，包含原始 Responses 输出项、工具调用与结果。网关检查这些历史是否包含上一轮完整上下文，符合时只向上游发送新增项和内部维护的 `previous_response_id`。历史、工具或推理等设置改变时会发完整上下文建立新响应链，不删除客户端提供的内容。客户端不需要填写 `prompt_cache_key`，已有字段仍透传。

断线、网关重启或令牌刷新后，在原账号用完整历史恢复，首次恢复可能零命中。连接空闲 10 分钟或接近 60 分钟的服务端寿命上限时会清理；内存仅保留上下文哈希，最多优先保留 128 个闲置会话，活跃请求仍由原有并发配置控制。账号或 Key 停用、删除、授权身份改变后，闲置连接会被关闭。未带 `session_id` 的独立请求、管理员连接测试和指纹采样继续使用 HTTP/SSE。

仅当上游首先返回 `previous_response_not_found`、尚未产生任何推理事件时，网关允许一次完整历史恢复；日志中的 `upstreamSession.attempts` 和 `recoveryAttempts` 会记录该过程。连接中断、部分生成和其他模型错误不自动重放，也不自动换号或降回 HTTP。默认传输方式为 `http`，也可用 `GATEWAY_UPSTREAM_SESSION_TRANSPORT=http` 明确指定。

请求详情和 CSV 保存 `upstreamTransport`、连接 ID、续接／恢复方式、父响应 ID、发送项数、恢复次数及返回缓存键哈希。响应头 `x-gateway-upstream-transport` 与 `x-gateway-upstream-session-mode` 可用于确认实际路径。缓存读取仍以原始 `usage.input_tokens_details.cached_tokens` 计量，`prompt_cache_diagnostics.type=unavailable` 不代表缓存未命中。

2026-10-12 的较早真实单 Agent 研究中，同账号、相同初始输入和工具定义，未发送上游 `session-id` 的 HTTP 17 次请求整体 token 命中率为 0.79%；持久 WebSocket 16 次为 89.23%，15 次续接全部命中。省略缓存键与填固定键的 WebSocket 小对照均约 94.9%。这些旧 HTTP 数据未包含本次补齐的会话请求头，不代表修正后的 HTTP 命中率。依据：[连接内续接及恢复](https://developers.openai.com/api/docs/guides/websocket-mode)、[套餐接入限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。

### Fast 与缓存验证

Fast 与缓存参数按调用者请求透传，是否支持和实际档位以本次上游响应为准。当前 Pro 路线的自动缓存已通过完整历史和真实工具循环验证；显式缓存配置、Fast 支持和历史实验边界见 [缓存与 Fast 验证记录](docs/cache-notes.md)。

## 详细用量与剩余量

SQLite 账本保存经本网关的请求，支持时间、账号、key、模型筛选、分页和 CSV 导出。包括：

- 请求与返回模型、执行状态、错误码、请求及响应 ID。
- 输入、输出、缓存输入、推理输出 tokens；缓存/推理是相应总量中的子集，不能重复相加。
- 总耗时、首个文本增量延迟、调用来源（agent、管理员测试或质量检查）。
- 按实际账号/key/模型的汇总及每日统计。
- 未确认完整用量的请求单列，不能据此声称没有消耗。

“剩余量”按来源分别显示：

1. **平台剩余限额**：自行配置的每日请求上限和 token 阈值，实时计算，属于本网关控制。
2. **官方 Codex 限额**：通过本机官方 Codex app-server 的 `account/rateLimits/read` 读取，分别显示各额度桶的短期/长期窗口、剩余比例和重置时间。`usedPercent` 是已使用百分比，剩余为 `100-usedPercent`（限制在 0–100）；空窗口和空字段表示未知，不能当作剩余 100%。优先采用 `rateLimitsByLimitId` 多桶数据，兼容旧单桶返回。不把 Codex 限额当作 Responses 接入或 ChatGPT 所有功能的总余额，不由 tokens 推算，也不据此自动换号。
3. **手工官方快照/上游限流头**：可以记录官方页面的剩余比例与重置时间，显示“手工”、记录时间和过时状态。上游 rate-limit 响应头单独展示，它不等于完整套餐剩余量。

每个账号需要一次独立的额度读取授权：账号行“连接额度读取” → “打开官方授权”，务必登录本行显示的同一邮箱。现有 SIWC 令牌没有可直接复用的明文 Codex 账号 ID，因此不从令牌中推测或解密账号信息。额度读取器使用每账号隔离的 `CODEX_HOME`，不会借用桌面或全局 CLI 的登录。官方登录后核对与 SIWC 登录的邮箱，再固定工作区；不同邮箱会断开额度授权，不保存其额度。模型授权身份变化时隐藏旧额度。授权完成后自动同步一次，也可点击“同步全部额度”或单账号“同步额度”。

服务运行时每 5 分钟自动读取已连接账号的限额，包括停用的账号。只发出账号/额度读取请求，不启动模型任务。超过 10 分钟未更新、同步失败或窗口越过重置时间时标为过时；保留旧值，不伪造恢复后的额度。界面显示更新时间和失败原因。一次只允许一个浏览器额度登录，以免官方回调端口冲突；可在弹窗取消。详情页可分别断开模型授权或额度授权。额外 credits 只有官方明确返回时显示，不当作金额或总 token 数。

需要本机安装 Codex CLI；优先使用桌面应用内置 CLI，否则查找 PATH 中的 `codex`。可通过 `GATEWAY_CODEX_BIN` 指定可执行文件路径。此额度读取方式用于本机演示，官方 app-server 授权不支持商业或托管服务。

手工快照超过一小时或越过记录的重置时间时标为过时。官方管理入口：[ChatGPT Settings → Usage](https://chatgpt.com/settings/usage)。

## 模型指纹与疑似差异提醒

- 请求和 API 报告的模型标识不一致时自动提醒。版本/别名映射也可能造成差异，不能独立证明后台实际执行模型。
- 采用 [ModelTrace](https://github.com/xqy2006/ModelTrace) 的数字指纹算法，已固定源码提交 `6cd4a8ff0f3f4e49d6d6969dd2fbadfa1569fde2` 和 18 模型参考库。原始评分器与 MIT 版权声明位于 `vendor/modeltrace/`，启动时核对库和评分器 SHA-256，不在运行时下载第三方代码。
- 每组发送 3 条独立数字挑战，请求约 300 个 1–355 的整数；固定同一账号、请求模型和推理参数，以 Responses 接口采样，不经过轮询，不给模型工具或业务历史，不修改用户指定模型。
- 分别计算数字出现频率和有序块特征，以 75% / 25% 融合；每组单独使用 ModelTrace 的校准评分。复测结果分别保存，不将多组权重相乘或冒充一个新的确定概率。
- 选账号和请求模型后直接测试，无需选择对照指纹标签。结果页直接显示全部 18 候选的归因权重，按权重从高到低排序；详细报告保留数字分布图、均值/分布熵/常见数字/末位频率，以及逐探针数字样本、提示词、有效数量、返回模型与 Response ID。
- 未收录新模型也可运行，显示候选及多组稳定性。`gpt-6.1-sol` 未包含在这个版本的库中，检测仍可显示其指纹偏向。归因总是对全部候选评分；后台仅以请求模型自动筛查疑似差异。旧客户端传入的 `expected` 不再影响新检测或定期检测，旧的手动对照设置退出新流程，历史报告保留。
- 完整 3 样本组中，对照为首位且权重至少 0.5 时显示相符；首位不同且权重至少 0.8、对照权重至多 0.15、两者差至少 0.65 时显示疑似身份差异。阈值取自 ModelTrace Guard，供筛查，不表示实际降智概率。其余偏离、未明显区分、有效样本不足分别显示。
- 可以选择异常追加 0–3 组复测：每次总计最多 3/6/9/12 个请求。强差异、同条件历史候选变化、未收录标签的高权重候选触发复测。多组同候选的强差异产生“多组指纹差异”提醒；出现分歧则保留分歧；未收录模型的多组同候选产生“候选线索”提醒。
- 检测历史默认显示全部账号，支持账号筛选、分页和详细报告。历史对照使用相同账号、请求模型、推理参数、算法与库版本的已完成结果，旧手动对照报告不混入新的自动筛查。检测请求在总用量账本中标为“指纹检测”，保留实际 token 消耗及未知用量。
- 无效数字样本、授权/额度错误与返回模型标识差异分别记录。部分有效输出仍可显示候选，但不作为完整差异证据；认证或额度等 4xx 错误停止后续探针。
- 可以停止后续检测请求；停用账号也会阻止后续检测。正在执行的请求可能仍会完成。
- 定期指纹检测默认关闭，可选择每 1/6/12/24 小时，保存后从下个间隔开始。沿用所选模型、参数和复测设置，会消耗对应账号额度。旧版答题检测的定期任务已关闭，旧记录/旧基线保留且可查看；旧 `/api/quality/run`、`policy`、`baseline` 返回 410。
- 结果用于详细疑似判断，展示库内相对权重。检测不会自动停用账号、降级模型或中断团队调用；可在账号池手动停用。未收录模型、采样环境和参数变化会影响解释，这些信息随报告保存。
- 提醒包括：授权需要处理、官方额度错误、本地限额、模型声明差异、疑似指纹差异、复测分歧、历史变化和新模型候选线索。提醒可直接打开对应检测报告。
- 管理操作另有审计记录，不记录 key 完整值、OpenAI 令牌或原始业务提示词。

## 接口

| 接口 | 行为 |
| --- | --- |
| `GET /v1/models` | 合并全局账号池模型目录，按 key 权限与模型可用性筛选 |
| `POST /v1/responses`，`stream:true` | 转发 SSE 事件，保留工具与完成事件 |
| `POST /v1/responses`，`stream:false` 或省略 | 等待完成事件，再返回完整 Response |
| `GET /v1/usage` | 只查看当前 key 跨账号的用量和平台限额；官方套餐额度按账号分别管理 |

上游使用 `https://api.openai.com/v1/responses`，始终发送 `store:false`、`stream:true`。字符串 input 转为单条用户消息；多轮上下文由调用者提交。不支持的套餐参数会明确报错。

如果上游没有 Content-Type，但内容是有效 SSE，仍能解析；若完成快照 output 为空，会使用同一响应的 `output_item.done` 项拼装。只有收到完成事件才视为成功。

不提供 Chat Completions/Anthropic Messages 转换、HTTP `previous_response_id` 存储或图像生成。函数工具还需遵循官方套餐接口的 namespace/additional_tools 要求；事件转发有模拟测试覆盖，真实工具闭环需按具体 agent 验证。

## 数据与访问范围

- 默认只监听 `127.0.0.1`；通过 `npm run start:lan` 可额外监听当前局域网私有 IPv4，内网管理需要独立管理员密码。服务器部署通过配置的 HTTPS 反向代理访问，管理员验证始终开启；部署配置见 `deploy/README.md`。
- 以下路径相对于运行数据目录，默认 `.data/`，服务器可配置 `GATEWAY_DATA_DIR`。根账号原有授权仍在 `.data/connection.json`；新增账号独立保存在 `.data/accounts/<id>.json`。
- Codex 额度授权单独保存于 `.data/quota-runtime/<id>/`，强制采用文件凭据存储；额度快照与身份绑定在 `.data/quota-state.json`。目录 `0700`，快照 `0600`，读取器不继承 API key 或外部令牌环境变量。私有身份绑定不会返回管理页面。
- host ID 和兼容默认 key 保存在 `.data/settings.json`；账号与 key 的配置在 `.data/management.json`；请求、提醒、审计和质量记录在 `.data/ledger.sqlite`。
- 凭据目录 `0700`、凭据文件和数据库 `0600`，`.data/` 已加入忽略文件。OpenAI 访问/刷新令牌不会返回浏览器。
- 原 demo 的授权与 key 保留；旧版保存的最近 200 次用量只迁入一次，原 JSON 不删除。v2 的 key 绑定与 v3 的自定义路由都会归档，统一使用全局池；迁移前配置备份到 `.data/backups/management-before-global-pool.json`。原有备份不删除。
- 账号分别由其所有者授权。成员使用网关接入 Key，管理员凭据和 OpenAI 令牌留在运行环境。
